# Product Discussion Log

## Summary

Mandy's Bike Finder evolved from a broad app-building learning project into a focused web MVP for parents evaluating used kids bike listings.

## Evolution

### Initial Exploration

The project began with a goal to build a real portfolio product and learn software product development. Several possible directions were considered, including local marketplace deal scouting, DIY planning, kids bike fit help, negotiation message assistance, and a digital health product canvas.

### Kids Bike Advisor Direction

The used kids bike advisor direction became the strongest because it had a real personal story: helping Mandy find the right used bike. It also had a clear target user and an understandable set of parent problems around sizing, price, condition, style, and seller communication.

### Platform Shift

The first platform idea was iOS, but the project shifted to a web MVP because web allows faster iteration and avoids App Store overhead. The web direction also better supports link input, screenshot upload, future price search, and easy sharing.

### Parent Decision Logic

The product expanded from simple fit advice into a broader parent decision helper. Color and style were recognized as real purchase factors for children's bikes. Numeric scores were replaced by qualitative red/yellow/green recommendations.

### Action and Retention

Negotiation Boost and Email Report were added so the product helps users take the next step after analysis. Backend metadata logging was added as a future analytics and monetization foundation, with privacy guidance to store buckets rather than unnecessary precise child details.

## Current Direction

The current source of truth is `docs/PRD.md` v0.4. The first implementation phase should be a front-end web MVP with mock/local logic, no real external APIs, and interfaces prepared for future search, OCR, email, and backend services.
