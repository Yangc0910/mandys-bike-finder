# Version 1.1.0 Plan

Status: Local and protected-preview regression complete; device and TestFlight verification pending

Theme: App polish, clarity, and trust

Development branch: `release/v1.1-ui-polish`

Production baseline: `v1.0.0-app-store-release`

## Release Intent

Version 1.1 is a controlled post-launch update. It should make the existing app feel more polished, easier to understand, and more trustworthy without expanding the product into accounts, payments, marketplace automation, or a new backend architecture.

## Product Goals

1. Make the app feel more polished and trustworthy.
2. Improve first-time user guidance.
3. Improve visual hierarchy on mobile.
4. Make the Evaluate flow easier to understand.
5. Make result cards more actionable and visually polished.
6. Improve History as a saved-decisions area.
7. Improve the Settings and Privacy trust surface.
8. Improve loading, splash, and launch behavior.
9. Prepare stronger App Store screenshots that resemble high-quality consumer apps.

## Planned Scope

- A documented visual system for typography, spacing, color, cards, buttons, icons, and states.
- Bottom navigation, safe-area, header, and app-shell polish.
- Better Profile onboarding and recommendation presentation.
- Clearer Evaluate input selection, upload, review, AI disclosure, and primary actions.
- A more actionable result hierarchy for fit, deal, risk, seller follow-up, and save.
- Better History cards, empty states, favorites, and saved-decision hierarchy.
- Cleaner Settings data controls, privacy messaging, and AI disclosure.
- Lightweight loading, launch, offline, error, and recovery states.
- A six-frame App Store screenshot story using controlled sample data.

Detailed UX requirements:

- `docs/prd/versions/v1.1.md`
- `docs/product/app-visual-system-v1.1.md`
- `docs/product/app-store-screenshot-storyboard-v1.1.md`

## Non-Goals

- Account, login, or cloud sync.
- Subscription, payment, or paid features.
- Marketplace scraping or automated listing monitoring.
- Bike Scout automation.
- Major AI backend or scoring changes.
- New provider integrations.
- Large architecture rewrite.
- Risky API behavior changes.
- A major Capacitor or native-platform rewrite.

## Release Requirements

- Profile local save, edit, and clear behavior still works.
- Evaluate retains local fallback and explicit AI actions.
- History local save, favorite, detail, and delete behavior still works.
- Settings local data controls still work.
- `/privacy` and `/offline` remain available.
- Initial load makes no OpenAI or LLM call.
- Provider keys remain server-side only.
- `www.mandysbikefinder.com` remains unaffected.
- `app.mandysbikefinder.com` changes only through intended, verified app UI releases.
- No marketplace scraping, account, payment, or subscription surface appears.
- Mobile regression testing passes before merge to `main`.

## Release Management

1. Keep `main` deployable and representative of the current production baseline.
2. Develop v1.1 through small tasks on `release/v1.1-ui-polish` or short-lived branches merged into it.
3. Use pull requests with screenshots and focused acceptance criteria for UI changes.
4. Verify the hosted app in a preview environment before production merge.
5. Run app lint/build for every implementation task and a mobile regression pass for the release candidate.
6. Merge the accepted release branch to `main`, deploy, verify production, and create `v1.1.0-app-store-release`.
7. Keep rollback possible by retaining the v1.0 tag and previous App Store build.

## Exit Criteria

- All v1.1 scoped tasks are accepted or explicitly deferred.
- No production guardrail regresses.
- Representative small and large iPhone layouts pass.
- Launch, offline, first-time, loading, error, and saved-data states are reviewed.
- App Store screenshot source states are reproducible.
- Release notes and version labels are updated.
- Production deployment and App Store build are verified before the v1.1 tag is created.
